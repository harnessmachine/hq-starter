# Issue tracker: локальные задачи штаба

Задачи, спеки и этапы этого штаба живут markdown-файлами в `tasks/`. GitHub не используется: не вызывай `gh issue create` и не ищи remote. `.scratch/` не создаётся.

## Устройство

- Одна задача — одна папка: `tasks/<slug>/`. `slug` латиницей через дефис: `site-prototype`.
- Задача: `tasks/<slug>/task.md` по шаблону `_system/templates/task.md`. Её заводит и ведёт скилл `manager`. В `TASKS.md` и `task.md` пишет только он.
- Спека: `tasks/<slug>/spec.md`.
- Этапы: `tasks/<slug>/issues/<NN>-<slug>.md`, по одному файлу на этап, нумерация с `01`. Никогда не одним общим файлом.
- Доска: `TASKS.md` в корне штаба, одна строка на задачу со ссылкой на `task.md`.
- История задачи — только `## Журнал` внизу `task.md`. Отдельных файлов передачи смены нет.

## Статусы

Три статуса, одни и те же для задачи, спеки и этапа. У задачи и спеки — строка `Статус:` у верха файла. У этапа — строка `**Status:**` из шаблона `to-tickets`.

| Статус | Значение |
| --- | --- |
| `в работе` | Можно делать или уже делается. Метка `ready-for-agent` из скиллов записывается этим статусом |
| `ждёт меня` | Пауза: нужен ответ, файл, доступ или решение владельца (в том числе после разговора с кем-то). Что именно — записано в журнале или в этапе |
| `готово` | Критерии приёмки выполнены. У задачи — только после подтверждения владельца |

Статус задачи меняется одновременно в `task.md` и в `TASKS.md`.

## Когда скилл говорит «опубликуй в issue tracker»

- Если разговор идёт по существующей задаче, пиши в её папку `tasks/<slug>/`.
- Если задачи ещё нет, сначала заведи её через `manager`, потом пиши в её папку.
- `to-spec` пишет `spec.md`, `to-tickets` пишет файлы в `issues/`. Сам `task.md` они не меняют. После публикации `manager` дописывает в журнал строку со ссылками на созданные файлы и добавляет этапы в «План».
- Вместо `.scratch/<feature-slug>/` из текста скиллов всегда `tasks/<slug>/`.
- Метка `ready-for-agent` = `Статус: в работе`.
- Запрет `to-spec` и `to-tickets` на пути к файлам относится к коду. Папки отдела, куда кладётся результат, называть можно.

## Когда скилл говорит «найди нужный тикет»

Прочитай файл по пути. Обычно владелец называет задачу или даёт путь. Если назвал словами, найди строку в `TASKS.md`.

## Задачи без кода

Большая часть задач штаба — исследования, тексты, решения, а не код. Тогда в `to-spec` и `to-tickets`:

- «изучи кодовую базу» = прочитай папку отдела и материалы задачи;
- «seams» и тесты = как проверить результат: файл, критерий, кто принимает;
- «вертикальный срез» = этап, после которого есть проверяемый результат (собранное сырьё, таблица, черновик текста), а не «половина работы».

## Этапы и блокировки

Файлы этапов пишутся по шаблону `to-tickets`: строки `**Blocked by:**` и `**Status:**` остаются, значения статуса — те же три. История этапа дописывается внизу его файла под `## Comments`.

`Blocked by` перечисляет этапы, которые должны быть `готово` до этого. Свободный этап — тот, у которого все блокирующие закрыты. Бери свободный этап с наименьшим номером. Закрыв этап, отметь его критерии, поставь `готово`, а `manager` допишет строку в журнал задачи.
